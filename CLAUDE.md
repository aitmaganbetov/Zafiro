# Zafiro — правила разработки

Laravel 13 + Pest + Vite/Tailwind 4. SaaS для компьютерных клубов: каждый клуб — тенант.

## Команды
- Тесты: ТОЛЬКО `composer test` (он делает `config:clear`).
  Никогда не запускать `pest` / `php artisan test` при закэшированном конфиге
  (`bootstrap/cache/config.php`): тесты используют RefreshDatabase и снесут рабочую БД `zafiro_db`.
- Линтер: `vendor/bin/pint --test` должен проходить перед коммитом (`vendor/bin/pint` — исправить).
- Сборка фронта: `npm run build`.

## Запросы к БД
- Не загружать связи, которые view не использует. Перед `with()` проверить шаблон.
- Агрегаты (суммы, счётчики, графики) считать в SQL (`SUM`, `COUNT`, `GROUP BY`),
  а не через `->get()` + фильтрацию коллекций в PHP.
- Не использовать `whereDate()` и функции над индексируемыми колонками в WHERE —
  фильтровать диапазоном (`>= startOfDay`, `< следующий день`).
- Списки, которые растут с данными (товары, пользователи, логи), — с пагинацией или поиском,
  а не `->get()` всего.
- Новые тенантные выборки по периоду или с сортировкой — проверять наличие составного индекса с `club_id`.
- Membership и подписка текущего клуба уже загружены в `CurrentClub` — не запрашивать их повторно.

## Тенантность
- Модели с `BelongsToClub` автоматически фильтруются по клубу; `withoutGlobalScope('club')`
  только осознанно и с проверкой доступа.

## Фронтенд
- Внешние скрипты и стили — только с закреплённой версией и только на страницах,
  которые их используют (`@push('scripts')`), не в общем layout.
- Не дублировать JS из layout во view (обработчики сайдбара и меню уже в `layouts/admin`).
- Не добавлять CSS-классы «на будущее»; удалять стили вместе с разметкой.

## Тесты
- Не хардкодить окружение (URL, порты) в ожиданиях — использовать `config('app.url')`, `route()`.
- Перед изменением логики расчётов — тест, сравнивающий результат со старой реализацией.
